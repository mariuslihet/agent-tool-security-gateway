# Operator control plane

The console opens in **Sample workspace** mode. Its data is a committed fixture generated by `npm run preview:build` from an isolated, in-memory gateway. The fixture generator never reads `.env` or the persistent database. Sample approvals and revocations are disabled, audit integrity is labeled sample data, and sample exports carry a `sample: true` manifest. Connecting to live data is always explicit.

## Workspaces

| Workspace | What you can do |
|---|---|
| Overview | Inspect persistent execution/denial totals, review queue size, session count, hourly activity, frequent denial reasons and recent decisions |
| Approvals | Search open records, filter pending/approved/expired requests, inspect transformed arguments and binding, record a decision note |
| Incidents | Investigate grouped high-risk signals, link source/session records, and track encrypted notes and version-checked dispositions |
| Safety Controls | Temporarily pause all/outbound reservations, inspect expiry and reason, and explicitly resume the current revision |
| Sessions | Page through tasks, filter the current page, inspect inherited data labels, capability grants, budgets and timeline; operators can revoke a session |
| Tool Catalog | Search registered contracts, distinguish internal/outbound tools, inspect input/output schemas and fingerprints; operators can revoke a tool within the tenant |
| Policy Studio | Edit a tab-local candidate, validate its contract, diagnose broad grants, compare active/candidate rule decisions and inspection restrictions |
| Policy Studio regression panel | Run up to 50 hypothetical cases with expected outcomes and download a policy/suite-bound report |
| Audit Explorer | Search metadata, filter event type/time, page a stable snapshot, inspect related sessions and download bounded JSONL exports |

Navigation supports keyboard focus, a skip link and `Ctrl K` / `Cmd K` quick navigation. Native modal dialogs handle focus containment and Escape. The layout adapts to narrow screens, uses tabular numbers for changing metrics, and respects reduced-motion preferences. Theme selection is the only browser-storage preference; credentials are not persisted.

## Roles

| Operation | Agent runtime | Viewer | Operator |
|---|---|---|---|
| Create task sessions / request execution | Yes | No | No |
| Inspect tenant activity, sessions, tools and policy | No | Yes | Yes |
| Validate/preview a hypothetical policy | No | Yes | Yes |
| Export tenant audit records / verify integrity | No | Yes | Yes |
| Approve, reject, cancel or revoke | No | No | Yes |

New `.env` files generated by `npm run init` contain separate agent, operator and viewer tokens. Existing configurations work without a viewer token; setting `GATEWAY_VIEWER_TOKEN` enables the optional role at startup. In this workspace a separate local viewer token has been generated without replacing existing credentials.

## Persistent metrics

The overview uses a derived SQLite index of authenticated audit records, not process-memory counters. Total executions, denials, review requests and average recorded execution latency survive restarts. The hourly chart covers the current hour and the preceding 23 hours; times render in the browser's local timezone. Counters describe events: an approval request and its later execution are separate events, not one combined request-total metric.

The original `Metrics` sink remains available for process-local instrumentation and latency samples. The status API distinguishes `statistics` (durable) from `metrics` (process-local).

## Audit investigation and export

`GET /v1/operator/audit` accepts `limit` (1–100), `cursor`, `type`, `tool`, `code`, `session`, `search`, `from`, and `to`. Time bounds are epoch milliseconds. Search is a literal, case-insensitive substring of event metadata. Filters and values use bound SQL parameters; arbitrary SQL, sort expressions and duplicate query parameters are rejected.

Pagination cursors are HMAC-authenticated and bound to the tenant, filter set and starting snapshot ceiling. New events do not shift later pages. Reusing a cursor with another tenant/filter or modifying its contents is rejected. Session cursors similarly bind the tenant and snapshot.

`GET /v1/operator/audit/export` uses the same filters except `limit`. It emits newline-delimited JSON with a manifest followed by at most 1,000 events. A truncated manifest contains `nextCursor`; pass it with the same filters to continue. Events include their signature and predecessor link. These are HMAC records, not publicly verifiable digital signatures; the signing key and an independently retained checkpoint are needed for independent integrity work. A filtered export is not a complete chain.

## Integrity and readiness

`/healthz` is process liveness. `/readyz` checks storage access and the current audit-health state/tail, returning only `ready` or `unavailable` without exposing tenant data. The Docker health check now uses readiness.

Full chain verification runs on startup and on **Verify full audit chain**, which calls `POST /v1/operator/audit/verify`. Ordinary dashboard refresh checks the tail and reports the time of the last full verification; it does not rescan the entire history. Corruption detected by verification latches the Store into an unhealthy state and blocks subsequent audited mutations. External signed checkpoints remain necessary to detect valid log truncation or rollback.

## Policy preview boundaries

`POST /v1/operator/policy/validate` validates a candidate and returns diagnostics. `POST /v1/operator/policy/preview` accepts the candidate, tool, arguments, hypothetical principal and hypothetical `sensitive`/`untrusted` labels. It returns active and candidate decisions, matching/nonmatching rules, inspection findings and redaction information.

No tool, session, approval, reservation or audit event is created by preview. It checks schemas, policy, sanitization and the modeled inspection restrictions. It **does not** evaluate actual task grants, budgets, revocations, existing approvals or concurrent operations. An allow in this studio is not execution authorization. Active policy publishing is intentionally host-controlled; there is no browser activation endpoint.

## Reviewer notes

Approval bodies may include a `reason` string of up to 500 characters. The console requires a short note before confirming a decision. The original note is encrypted with its request record; queue previews redact known secrets and PII. Audit records contain only the note's SHA-256 fingerprint, plus the approver, binding and decision. Do not use notes as a general secret-storage channel.

## Client library

```js
import { ControlPlaneClient, GatewayApiError } from '../src/index.js';
const operator = new ControlPlaneClient({ token: process.env.GATEWAY_VIEWER_TOKEN });
const status = await operator.status();
const page = await operator.audit({ type: 'execution.denied', limit: 25 });
const sessions = await operator.sessions({ limit: 25 });
const exportedJsonl = await operator.exportAudit({ type: 'execution.denied' });
```

Other methods: `session`, `policy`, `validatePolicy`, `previewPolicy`, `decideApproval`, `revoke`, and `verifyAudit`. Authorization remains server-side. The SDK keeps its bearer token in a private field and provides `GatewayApiError` with code, HTTP status, correlation ID and retry-after seconds. It never retries side effects automatically.

The reference server allows 120 authenticated requests per credential per minute, with an additional shared budget of six full-verification/export requests per credential per minute. Rate-limit responses include `Retry-After`; responses also carry `X-Request-Id` and general rate-limit headers. These counters are process-local, not a distributed edge limiter.

## Upgrade behavior

On opening a 0.1-style database, the Store builds its audit index from verified existing records. Signed events, encrypted sessions, requests and idempotency outcomes are retained. Tool descriptions/contracts were improved in 0.2, which changes their pinned fingerprints; older task sessions can therefore show `configuration_changed`. Start a newly authorized task instead of attempting to bypass that binding.
# Investigation additions in 0.4

The console now has ten workspaces. **Request Explorer** filters persisted outcomes and opens a recent per-request timeline. Explicit argument inspection requires an operator credential and a reason, with an audit record before disclosure. **Security Alerts** lets operators configure rolling threshold rules and maintain version-checked dispositions. Overview downloads a metadata-only workspace report. See [investigation, local alerts and reporting](investigation.md) for limits, role boundaries and retention behavior.

## Scoped response in 0.5

**Safety Controls** adds a scoped hold form, exact-target confirmation, active/all-target filters and audited release. Session and tool detail dialogs prefill that form. **Overview** adds read-only health diagnostics for operational follow-up; sampling coverage is explicit. Viewer access supports investigation while mutations require an operator. See [scoped containment and workspace health](scoped-containment.md).
