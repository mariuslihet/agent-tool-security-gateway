# Real local AI with Ollama

For real local document work, see [workspace tools](workspace-tools.md). Select Workspace mode to search/read reviewed text and create a local report after exact-request approval. Safe mode retains its original grants.

Version 0.7 adds [follow-up messages, per-task tool modes, usage statistics and conversation exports](conversations.md). New tasks default to the safe tool set. The original 0.6 workflow below still describes starting independent tasks; a completed task can now also be continued through its separate follow-up form without resetting its session or budgets.

The AI Agent page uses a real local model. It sends your task and tool definitions to Ollama, passes model-proposed function calls through the gateway, then returns permitted tool results to the model for its generated response. There is no canned-response fallback. Existing dashboard sample data is separate and never drives model answers.

The implementation follows Ollama's [native chat API](https://docs.ollama.com/api/chat) and [tool-calling protocol](https://docs.ollama.com/capabilities/tool-calling). It uses Node's built-in HTTP client, without adding runtime dependencies.

## Setup

1. Install and start Ollama using its [Windows guide](https://docs.ollama.com/windows), or use an existing installation.
2. Install a tool-capable local model. This workspace was verified using the already-installed `qwen3.5:4b`. For a new installation, pull the model you intend to use, for example `ollama pull qwen3.5:4b`.
3. Add non-secret settings to the gateway `.env`:

```dotenv
LLM_PROVIDER=ollama
LLM_MODEL=qwen3.5:4b
OLLAMA_BASE_URL=http://127.0.0.1:11434
```

4. Restart `npm start`, open **AI Agent**, connect using `GATEWAY_OPERATOR_TOKEN`, and choose **Test model connection**. Submit your own task.

No API key is required. Endpoints are restricted to numeric loopback HTTP addresses (`127.0.0.1` or `::1`), redirects are rejected, and the reference adapter does not accept remote model endpoints. Use an installed local model and keep the trusted Ollama service configured for local inference. The gateway does not control or certify the Ollama installation itself.

The configuration check verifies the installed model advertises function-tool support. It does not guarantee a model will choose the right tool or produce correct prose. Unsupported/missing models and unreachable services return explicit errors; they never trigger fabricated model responses.

## Task workflow

**Start new AI task** creates a new gateway session and task. The conversation displayed for that task includes its user prompt, model-generated text and a gateway execution trace. Separate tasks do not share chat memory. A completed task can be reopened from encrypted history and continued through **Ask a follow-up** while its original session and task budgets remain valid.

Tools use stable aliases in model context because provider function-name restrictions differ from registry names. The host resolves aliases against the session's pinned catalog. Model output cannot choose an actor, tenant, arbitrary function, shell command or adapter. Schema checks, capability grants, policy, provenance, budgets, approvals, revocations and containment remain in the gateway.

Before executing any proposed call, the runtime persists its exact original arguments and a stable gateway request ID. The model cannot authorize itself. A denied call becomes a structured tool response so the model may propose a valid alternative within its finite budget.

Approval-required and paused responses stop the loop with `state: waiting`. Make the separate operator decision in Approvals or Safety Controls, return to AI Agent and select **Resume exact pending call**. The same request ID and arguments are retried; the model does not regenerate the request. Indeterminate execution stops the task for reconciliation and is never automatically retried with a new ID.

Sensitive/untrusted session labels and detected secrets/email in tool output stop forwarding to the model, including local models. The operator receives `MODEL_DATA_WITHHELD`, without that tool payload in the conversation. Reading the confidential invoice or injection fixture therefore demonstrates withholding rather than allowing the model to summarize classified data. Provider text itself remains untrusted; only gateway trace entries establish that a tool executed.

**Stop task** aborts further model work and prevents later tool dispatch after the current await completes. An already reserved tool may still finish and is audited by the gateway. Switching pages, disconnecting the browser or closing a tab does not cancel a server-side task.

## What is real and what remains a fixture

| Component | Behavior |
|---|---|
| LLM prose and function selection | Generated by installed Ollama model at request time |
| `compute.sum` | Runs validated arithmetic in the fixed restricted worker |
| `text.encode` | Actually encodes supplied text |
| Handbook, external page, invoice | Fixed reference fixtures with explicit provenance labels |
| Publishing and payments | Simulations; no delivery or charging |
| Authorization and audit | Real enforcement and persistent records |
| Public dashboard preview | Pre-generated isolated sample; cannot run AI tasks |

New tasks ask the model again. Similar prompts may naturally produce identical wording or arithmetic results. Reusing an existing task ID with the same prompt intentionally returns stored state; changed prompts with that ID are rejected. No artificial random answer substitution is used to create the appearance of a model.

## Bounds, state and recovery

The reference limits are 100 retained tasks per tenant, two active workers across a shared database, 6 model turns and 12 finished tool evaluations per task, 4 proposed calls per model response, 8,000 prompt characters and 6 minutes per active run attempt. Each provider call has a 120-second timeout, up to 1,024 generated tokens, an 8,192-token context setting, a 128 KiB serialized request bound and a 256 KiB response bound. Tool messages above 16 KiB are withheld by a typed error rather than silently truncated. Requests exceeding conversation/storage limits fail explicitly. The provider rejects truncated generations.

Task state (prompts, assistant text, catalog and pending arguments) is AES-GCM encrypted using the existing storage key. Audit contains task/session/principal identifiers, state codes and prompt hashes, not transcript text. Conversations are operator-only; viewers can inspect non-secret model configuration but cannot read task history or generate/resume/cancel tasks. These capabilities are tenant-scoped. No task deletion or retention cleanup endpoint is included.

SQLite leases prevent separate workers from concurrently owning one task. A graceful gateway shutdown aborts its model requests and releases its own leases. After an unclean process termination, an outstanding lease expires within roughly eight minutes before another worker can resume. Tasks are not automatically restarted. GET returns `interrupted` when queued/running state has no live lease; explicit resume reuses pending calls. Gateway idempotency also protects the tool reservation if a crash occurs between dispatch and recording the tool message.

Task start may create an audited session before task-record insertion; a failed start can leave an unused session, but no tool is dispatched without persisted task state. Changing the configured model requires a new task; existing tasks cannot be resumed under a different model. Start/resume/check/cancel share the control plane's heavy-operation rate budget. Polling status uses the normal request budget.

## Verification

```powershell
npm test
npm run ai:smoke
```

Offline tests use controlled providers to exercise security outcomes deterministically. They are not evidence of real inference. `ai:smoke` is a separate opt-in check against the actual running gateway and Ollama; it requires a completed `compute.sum` trace and prints model text. Browser verification can opt into a real local model on the disposable in-memory QA host with `GATEWAY_QA_REAL_LLM=1`; it does not read `.env` or live storage.
